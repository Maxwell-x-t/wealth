# 红利网格提醒（dividend-grid-reminder）

红利网格仓位管理策略。核心原则：**逐股生成股息率信号，再通过分红质量和统一资金限制生成可执行目标。**

2026-09-11：实盘与回测已共用财年分红和现金覆盖买入限制，银行核心一级资本字段已修正，并新增实际股数和现金估值模式。使用方法见 [当前规则与账户登记](STRATEGY_RULES.md)，最新结果见 [新版策略回测](backtests/results-coverage-20260911/REPORT.md)。下方旧历史报告未包含这些质量限制，不代表现行策略收益。

- 买入（越便宜越买，累计目标）：默认股息率 ≥ 5.1% / 5.6% / 6.0% 时目标 6 / 9 / 12 份；**金融**抬高为 ≥ 5.5% / 6.0% / 6.5%。
- 卖出（越贵越卖，逐档减仓）：跌破 4.9% / 4.6% / 4.2% 逐档卖 3 / 3 / 4，普通网格最低保留 2 份底仓；已确认的基本面退出可清仓（金融卖出阈值与默认相同）。
- 持有带：默认 4.9%~5.1%；金融因买入门槛更高，持有带为 **4.9%~5.5%**（不够便宜不加、不够贵不减）。
- 现金仓位 = 100% − 个股持仓 − ETF 当前持仓。默认个股 1 份 = 1% 总资产，ETF 1 层 = 2% 总资产。


## 512890 周 RSI6 价格提醒

`512890` 使用周线 Wilder RSI(6) 价格提醒，标的代码固定为 `sh512890`。ETF 不进入个股清单或股息率网格，但与个股共用总资产预算；10 层满仓为总资产 20%。接入 Wealth 后从统一账本读取实际份额与层数；独立的旧文件模式才读取 `rsi6_holdings.json`。

- RSI6 `> 80`：价格触发全仓卖出。
- RSI6 `> 74`：每周首次进入卖区时记录持仓，累计减 2 层，最多卖出当时持有的层数。2 层等于 ETF 满仓额度的 20%，即总资产 4%。
- RSI6 `< 31 / 25 / 20`：价格分别触发买入至 `4 / 7 / 10` 层；买入区内当前层数高于目标时维持，不主动减仓。
- 采用周内触发：用最近交易日价格更新本周 RSI，触发价以上一根已完成周 K 的 Wilder 平滑均值反推。多档同时触发只执行最深档目标，不叠加。
- 两种运行模式均记录本周卖出目标；成交后更新实际层数，同一档不会反复卖出。发生卖出信号后本周暂停买入；`>80` 仍可升级清仓，下周重置。
- RSI 使用前复权连续价格并对齐最新交易价格，避免除息被当作下跌。东方财富失败时使用腾讯新版接口明确标记的前复权序列（最近约 640 个交易日，保留 ETF 价格精度）。历史起点不同时截取共同区间；最新交易日不一致、中间日期缺失或两源均不可用时停止计算，不回退到未复权指标。

手动运行：

```bash
uv run python scripts/rsi6_calculator.py --session morning --notify console --notify-on always
uv run python scripts/rsi6_calculator.py --session close --notify console --notify-on always
```

`--mode layers` 输出可执行层数，默认 `--mode market` 输出价格触发提醒；二者共用阈值、资金约束和 `rsi6_state.json`，不会把计划当作成交更新持仓。

## 统一资金限制

`portfolio_rules.json` 同时供个股和 ETF 提醒读取：

```json
{
  "min_cash_pct": 20.0,
  "max_industry_pct": 30.0,
  "industry_limits": {},
  "etf_budget_pct": 20.0
}
```

**三分类凑满 100%**（个股上限不是独立字段，而是推导值）：

| 类别 | 配置字段 | 当前 | 2026-09-10 | 2026-09-11 前 |
|---|---|---:|---:|---:|
| 个股合计上限 | `100 − min_cash_pct − etf_budget_pct` | **60%** | 50% | 70% |
| 现金下限 | `min_cash_pct` | **20%** | 30% | 10% |
| ETF 预留 | `etf_budget_pct` | 20% | 20% | 20% |
| **合计** | | **100%** | 100% | 100% |

- 现金下限 **20%**（2026-09-11 由 30% 下调），个股单行业上限暂设为 30%；可通过 `industry_limits` 为现有行业标签覆盖上限。这些是风险设置，不是经过收益回测的最优参数。
- **现金下限怎么来的**：当前20%由用户设定。旧熊市样本中回撤与仓位的拟合关系只描述那组样本，不能视为恒等式或未来回撤保证。历史参数扫描见 [稳健性补记](backtests/ROBUSTNESS_NOTE.md)。
- ETF 总额度固定预留 20%，尚未持有的部分仍属于现金但不允许个股占用，因此**个股新增目标最多合计 60%**（100% − 20% 现金下限 − 20% ETF 预留）；ETF 满仓时合计权益暴露上限约 80%。ETF 买入还会核对实际个股持仓，现金不足时向下取整为可买入的完整层数。
- 个股先计算卖出后的持仓占用，再按行业限额及剩余现金等比例缩减各买入信号。提醒中的份数可能带小数；买入金额不得超过目标，执行顺序为先卖后买。
- 已超行业或现金目标的仓位不会仅因限额被强制卖出，但暂停相应新增买入并提示。行业限制目前覆盖直接持有个股，不穿透 ETF 成分股。
- 行情缺失的股票仍计入资金占用，并暂停全部个股新增买入。持仓文件缺失、已有持仓不在清单内、重复代码或总持仓超过 100% 时停止计算。
- 接入 Wealth 后，网页登记的成交自动更新实际股数、现金和 ETF 层数。独立使用旧文件模式时，两份持仓文件必须按实际成交和当前净值更新；程序不连接券商核实仓位。自定义个股 `weight` 或 `--pool` 时，ETF 侧必须读取相同清单并使用相同 `--pool`。

### 本地定时运行

`scripts/local_reminder.sh` 会在同一时点依次发送原有股息率网格提醒和 512890 RSI6 提醒。使用 macOS `launchd` 每天 **09:00**、**09:30**、**14:00** 和 **15:05** 运行；脚本为每个时段保留有限的延迟窗口，以容忍电脑唤醒或系统负载造成的启动延迟，同时避免任意时间手动运行时误发：

双击 `strategy/start_local_reminder.command` 安装或更新任务；安装器按当前仓库位置生成 launchd 配置，不依赖旧工程目录，也不会立即推送。首次运行若未找到凭据，会生成 `.env.local` 模板，填入企业微信 Webhook 后再次双击即可。提醒优先读取本目录 `.env.local`，否则读取 `~/Library/Application Support/dividend-grid-reminder/.env.local`。

需要停止时，双击 `strategy/stop_local_reminder.command` 即可取消本地定时任务。

```bash

```

`.env.local` 已加入 `.gitignore`。日志写入 `/tmp/dividend-grid-reminder.log` 和 `/tmp/dividend-grid-reminder.error.log`。本仓库通过本地任务读取实际账本，不配置 GitHub Actions 交易提醒。

### 主要参数

- `--stocks`：个股清单，格式 `代码:名称[:股息率%[:权重[:分组]]]`。`manual` 源必须带股息率；`akshare` 源可省略。与 `--stocks-file` 至少提供一个。
- `--stocks-file`：监控清单文件（默认配合 `watchlist.json`），akshare 自动取股息率。
- `--holdings`：临时持仓 `代码:份数`；不传则读 `holdings.json`。
- `--source`：`manual`（默认）/ `akshare`（实际默认走腾讯财经免登录行情；若设置 `XQ_A_TOKEN` 则优先雪球）。
- `--notify`：`none`（默认）/ `console` / `wecom`。
- `--notify-on`：`signal`（有买卖信号才推，默认）/ `always`（每次都推；定时任务用这个）。
- `--pool`：单只满仓净值比例（默认 0.12）。
- `--groups-file`：行业分组阈值（默认 `./strategy_groups.json`）。
- `--quality-file`：分红质量规则（默认 `./quality_rules.json`）。
- `--portfolio-file`：统一资金限制（默认 `./portfolio_rules.json`，两套命令均支持）。
- `--etf-holdings-file`：网格侧读取的 ETF 层数文件（默认 `./rsi6_holdings.json`）；RSI 侧对应参数为 `--layers-file`。

### 配置文件（当前工作目录）

- `account.json`：可选的实际股数、ETF份额和现金账户；存在时两套提醒优先按市值核算。示例结构见 `account.example.json`，需填写真实数值。
- `holdings.json`：未启用实际账户时使用的 `{"股票代码": 当前份数}`，需手工按最新净值校准。
- `dividend_overrides.json`：每股分红金额、依据日期及失效日期，按最新价格计算股息率，输出标 `*`。旧的固定百分数格式已停用；海尔智家已恢复实时股息率。
- `watchlist.json`：监控清单，配合 `--stocks-file`。支持带行业标签：`{"代码": {"name": "名称", "group": "行业"}}`，也兼容旧格式 `{"代码": "名称"}`（归 `default` 组）。
- `strategy_groups.json`：行业分组阈值 `{"分组": {"buy": [b1,b2,b3], "sell": [s1,s2,s3]}}`。未配置的分组回退到 `default`。
- `quality_rules.json`：派息率警示/高风险阈值，以及是否否决高风险买入。

分红覆盖格式示例（金额应使用核实后的年度/TTM 每股现金分红，不可直接将单次中期分红当作全年金额）：

```json
{
  "示例代码": {
    "dividend_per_share": 1.2,
    "as_of": "2026-09-01",
    "expires_on": "2026-12-31"
  }
}
```

覆盖过期、缺少最新价格或仍使用旧格式时标记数据不可用并暂停新增买入；覆盖后的派息率也按同一每股分红金额重新计算。

## 行业分组阈值

不同行业的股息率中枢不同，用同一套阈值会系统性超配高息行业。可按行业分别设阈值：份数结构不变（买入目标 6/9/12、卖出保留 9/6/2、底仓 2），只调股息率档位。持有带 = [最高卖出阈值, 最低买入阈值)。

- `default`：买 `5.1 / 5.6 / 6.0`，卖 `4.9 / 4.6 / 4.2`。
- `金融`（天生高息，**只抬高买入门槛**）：买 `5.5 / 6.0 / 6.5`，卖 **`4.9 / 4.6 / 4.2`**（与默认相同）。持有带因此为 `4.9%~5.5%`。
- 其余行业（消费/公用能源/电信等）未单独配置，回退到 `default`。

每只标的在 `watchlist.json` 里用 `group` 打标签；输出会带「行业」列与「行业集中度(当前→目标)」汇总。

## 分红质量过滤（Phase 1：派息率）

规避"价值陷阱"——高股息但不可持续。用腾讯行情的股息率 TTM 与市盈率估算**派息率 ≈ 股息率% × 市盈率**（等价于 DPS÷EPS；若有雪球 token 则用雪球的股息/EPS）：

- `> 100%`：🔴 风险待复核（分红超过该口径盈利，需核对特别分红、现金储备等原因）
- `>= 80%`：🟡 警示
- `EPS ≤ 0` 仍分红：🔴 高风险
- 其余：✅ 健康；manual 数据源无 EPS → ⚪ 数据不足

当前配置启用**暂停高风险及质量未知标的买入**，卖出不受影响。没有仅凭派息率自动清仓；对已经人工核实的重大基本面问题，在 `exit_reasons` 逐股填写原因后可清仓并持续阻止重新买入。

```json
{
  "payout_warn": 80,
  "payout_risk": 100,
  "flag_negative_eps": true,
  "veto_buy_on_risk": true,
  "veto_buy_on_unknown": true,
  "exit_reasons": {}
}
```

### 分红质量过滤（Phase 2：现金覆盖 / 银行监管指标）

在派息率筛查之上，进一步用**自由现金流覆盖**判断分红是否「有现金支撑」，并对**银行**改用监管指标。逻辑封装在 `dividend_grid/coverage.py`，每日随提醒自动运行：

- **非银行**：`FCF ÷ 现金分红`。**主判据取近 5 个完整财年的合计口径**（ΣFCF ÷ Σ分红），以平滑单年资本开支波动；不足 3 个分红年度时回退单窗口 TTM。≥1.5x ✅ 达标、≥1.0x 🟡 裕度不足、<1.0x 🔴 盖不住分红。
  - 窗口 = 最近的完整财年（连续、不跳年）；只有明确不分配记录才计零分红。缺现金流或分红记录时不跨过该年拼凑窗口，年度资料不足则暂停新增买入待复核。
  - 采用合计而非年度比值的简单平均：单年 FCF 可能为负，两种口径都会给出，但**打标以合计口径为准**。
- **银行**：FCF 无经济含义，改取三项监管指标——核心一级资本充足率（<10% 🟡 / <8.5% 🔴）、不良贷款率（>1.5% 🟡 / >2.0% 🔴）、拨备覆盖率（<200% 🟡 / <150% 🔴）。
- **数据源**：FCF 用**新浪财报现金流量表**（经营现金流 − 购建长期资产支出，取 40 期覆盖约 10 年）；分红总额用**东方财富分红明细** `RPT_SHAREBONUS_DET`（`每 10 股派息 ÷ 10 × 总股本`，按 `REPORT_DATE` 年份归集，只计已实施）；TTM 分红另用「股息率 × 总市值」校验。**口径必须统一**：腾讯自选股的 FCFF 含投资/理财流出，会显著低估 FCF（伊利 FY2025 腾讯口径 0.39x、新浪口径 1.30x），本项目统一采用新浪口径。
- 取数失败或覆盖度不足时降级为 `unknown`，仍显示报告，但暂停新增买入；`--no-coverage` 跳过检查时也不能绕过该限制。实盘财年分红不再当作 TTM 分红混用。

阈值可在 `dividend_grid/coverage.py` 的 `CoverageConfig` 调整（`fcf_pass=1.5`、`fcf_years=5`、`fcf_min_years=3` 等）。控制台表格与企微消息均新增「分红可持续性」段落，显示形如 `🔴华能国际 -4.67x（5年）`。独立分析用 `uv run python scripts/fcf_coverage.py --detail`（输出 TTM / FY / 近3年 / 近5年 / 年均 与逐财年明细）。详细推导见 [FCF_COVERAGE.md](FCF_COVERAGE.md)。

当前质量管道覆盖派息率、连续年度现金覆盖及最新年度趋势、银行监管指标。保险公司需专项复核，不使用一般企业 FCF 倍数；负债期限和维持/扩张资本开支仍需人工判断。本次未调整股息率买卖阈值，也未用历史数据优化参数。

## 行情数据源

`--source akshare` 默认请求腾讯财经 `qt.gtimg.cn`（免登录）。行情里的「股息率 TTM」字段**不用于买卖判定**，只作为分红质量的兜底；股息率本身由东方财富分红明细按下面这条口径规则重算。雪球个股接口现已要求登录，GitHub Actions 无 cookie 时会报 `400016`。若要用雪球，设置环境变量 `XQ_A_TOKEN`（或 `XUEQIU_TOKEN`）为浏览器 cookie 里的 `xq_a_token`；无效时自动回退腾讯。

### 股息率口径（通用规则）

**所有标的、所有通道（日常提醒与回测）统一按财年口径计算股息率——不逐股配置，也没有有效期。**

规则（代码唯一来源：`dividend_grid/dividends.py` 的 `CALIBER_RULE`）：

1. 先确定最近一个「年度分红（12-31 报告期）**已实施**」的完整财年；
2. 汇总该财年**全部已实施分红（含中期分红）**，并按此后发生的送转调整每股口径；
3. 除以最新价得到股息率。

若该财年含已标识的特别分红、方案被取消、或多年没有新的年度分红实施，则判定口径不可用（暂停买入），而不是把股息率当 0 处理。

**为什么不用滚动 12 个月**：滚动窗口与「钱什么时候到账」强绑定。取消或推迟一次中期分红，股息率就会机械跳水——与估值无关，却会触发卖出。财年口径只随「这个完整财年一共分了多少」变化，与支付节奏解耦。

实证（海尔智家）：FY2025 = 中期 0.2692 + 年度 0.89151 = **1.16071 元/股**；FY2026 中报公告不分配。按财年口径，该值在 2026-11-07（中期分红除息满一年）之后**保持不变**，直到 FY2026 年度分红实施才切换到新财年；而滚动 12 个月口径会在同一天从 1.16071 掉到 0.89151（**−23%**，股息率 5.52% → 4.24%，恰好跌进卖出档，是一个纯日历造成的假信号）。回归测试见 `tests/test_dividend_caliber.py`。

提醒输出会显式打印本批口径与实际使用的财年，避免把口径误读成 TTM：

```
股息率口径：财年口径（最近一个「年度分红已实施」的完整财年，含该财年中期分红；非滚动 12 个月）· 本批统一 FY2025，每股分红 0.2410~4.7037 元
```

`dividend_overrides.json` 因此只在**行情口径确实失真**时才需要，且必须写「每股分红金额 + 有效期」（生效期内用声明值 ÷ 实时价计算）；日常运行不需要维护覆盖表。

### 股息率口径（重要）

> 规则的完整说明（含为什么不用滚动 12 个月、以及海尔的实证）见前面的 [股息率口径（通用规则）](#股息率口径通用规则)。本节记录它在回测里的量级。

每股分红按**财年口径**计算：先确定最近一个「年度（12-31 报告期）分红已实施」的完整财年，再汇总该财年全部已实施分红（含中期分红），并按此后发生的送转调整每股口径。

早期版本使用「过去 365 天已实施分红求和」，在除息日逐年漂移几天时会**同时装进相邻两个年度的分红**（当年多计），漂移出窗口时又漏计，导致档位反复翻转。实证：招商银行 2019 年除息 07-12、2020 年 07-10，旧口径下 2020-07-10 股息率被算成买入档，回测在 2020-07-13 买入 1,600 股、次日又卖出 1,000 股。全样本含 7 笔此类 7 日内往返，修正后降到 1 笔，手续费与滑点合计下降约一半。

回测保留 `caliber="naive"` 复现旧口径，用于量化误差：同一策略旧口径年化 11.47%、修正后 **8.67%**。**旧口径结论已作废。**

### 数据正确性修复：财报披露日期偏差

上游新浪财报接口对 **2025-06-30 及更早**的报告期，`publish_date` 字段整体多算了一年；而同一响应里的 `update_time`（Unix 时间戳）与真实披露时间吻合。按前者使用会让基本面滞后一年，并在相邻年度交界处造成约 5 个月的 TTM EPS 空窗（例如华润江中在 2025-10-27 至 2026-03-19 之间缺失 96 个交易日）。

修正后以 `update_time` 为准，仅当它缺失或晚于 `publish_date` 时才回退。本批数据 1,209 条财报记录中有 **485 条被修正（40.1%）**，空窗降为 0 天。`scripts/rebuild_backtest_data.py` 可从已缓存的原始响应离线重算。

影响只落在依赖质量筛查的网格类方案上（当前策略 7.88% → **8.67%**，仅股息率网格 5.86% → 6.58%）；**纯 RSI 方案与关闭质量筛查的方案完全不读财报，数值逐项不变**——这本身就是一次有效的交叉验证。

### RSI 参数敏感性：周期 × 阈值平移

既已怀疑 RSI 择时的优势来自特定行情，进一步检验它对参数有多敏感：把 **RSI 周期**（4/6/9）与**所有买卖阈值的整体平移量**（-4/-2/0/+2/+4 点）做成网格，在两个窗口上各跑一次完整回测（共 60 次）。

**核心发现：参数曲面没有内部最优。**

| 策略 | 窗口 | corr(平均权益暴露, 年化) | 收益最优 | 效率最优 |
|---|---|---:|---|---|
| 分层版 | 2019-2026 | +0.957 | 周期 4 / 平移 +4（13.55%）边界 | 周期 9 / 平移 -4（0.702%）边界 |
| 分层版 | 2022 起 | +0.801 | 周期 4 / 平移 +2（13.73%）内部 | 周期 9 / 平移 -4（0.984%）边界 |
| 梭哈版 | 2019-2026 | +0.885 | 周期 6 / 平移 +4（13.62%）边界 | 周期 9 / 平移 -4（0.423%）边界 |
| 梭哈版 | 2022 起 | +0.913 | 周期 4 / 平移 0（13.07%）内部 | 周期 9 / 平移 -4（0.421%）边界 |

- **收益几乎完全由仓位解释**：30 个格子里，年化收益与平均权益暴露的相关系数都在 +0.80 以上。平移越大＝越早进场＝暴露越高＝年化越高；平移越小＝越少交易＝暴露越低＝「单位暴露效率」越高（该指标本身是暴露的递减函数，故效率最优 4/4 全落在几乎不交易的 -4 边界，那一列暴露只有 4%~15%，数值已失真）。**当前配置（周期 6、平移 0）两头都不是最优。**
- **收益最优也不稳定**：只有两个窗口落在 +4 边界；另两个落在周期 4 的内部，且**最优位置随窗口移动**——梭哈版周期 4 在全样本最优于平移 -2（13.27%），到 2022 年起却移到平移 0（13.07%）；分层版 2022 年起的 +2 与 +4 只差 0.01pt，实为平台而非峰点。
- **周期 6 也不是收益最优**：平移 0 时，分层版周期 4 得 11.74%、周期 6 得 9.26%、周期 9 仅 3.79%（全样本只交易 8~9 笔，等于长期空仓）。换一个在设计上没有优劣之分的周期，年化就能改 2.5 个百分点。

这与全样本、子区间得到的结论一致：**决定结果的仍是「持有多少」，而不是「RSI 择时有多准」**。完整热力图与逐格数据见 [RSI 参数敏感性报告](backtests/sensitivity-rsi-20260910/REPORT.md)。

**抗跌是真的，但来源不是 RSI 择时。**

- **抗跌来自股息率网格的估值闸门。** 2007 年 1-10 月上证红利ETF 涨 164%，把个股股息率压到阈值之下，网格判定「太贵」→ **`grid_only` 整个 2007 年零成交、零仓位**，2008 年全年 +2.82%、年内最大回撤 -1.09%。它躲过 2008 不是靠预判，而是靠「贵到不该买」这条机械规则。
- **RSI 择时在单边慢熊里是风险来源。** 把 RSI 单独拿出来（全仓 ETF），2007-11-28 RSI6 读到 30.7 就开始建仓，2008 年 3 月 RSI 继续走低到 22.4 / 18.7 时继续加仓，到 2008-10-28 已持 77.2% 仓位，**2008 年亏 56.00%**（同窗口最大回撤 -61.18%），与满仓持有（-54.22%）几乎一样惨。
- **同一个 RSI 逻辑在 2015 却有效**：2015-06-12 见顶时 RSI 在高位、已清仓，躲过股灾，当年 +8.02%。**它在「急跌急反弹」里有效，在「慢性单边熊市」里是陷阱。**
- **代价是长期收益**：当前策略 2008 窗口年化 4.02%（买入持有 12.94%）、2015 窗口 6.90%（买入持有 19.16%）。策略在泡沫期缺席，而那正是长期收益最集中的时段。

这也解释了主回测的「单位暴露效率高、绝对收益低」不是参数问题，而是这类策略的固有取舍。

**数据修复（新）**：腾讯行情接口在 `sh510880` 上返回过一个孤立坏点——2008-01-02 记成 1.467 元，而前后交易日分别是 4.637 / 4.794。它会伪造一次 -68%/+227% 往返，并使周线 RSI 误判超卖而假买入。现在 `fetch_prices` 会剔除「单日收盘相对前后两个交易日都偏离 50% 以上」的孤立跳变；判定要求**双向偏离**，因此不会被真实的除权跳空误伤（例如 510880 在 2009-03-24 每份分红 1.0 元、价格从 4.5 掉到 1.5 属于单边偏离，保留）。已按此规则 `scripts/repair_backtest_prices.py` 离线重算：熊市数据集 15 个标的、约 3.8 万根日线里**仅此 1 条**被剔除；主数据集（2017 起）0 条，故主回测结论不受影响。

### 由熊市检验引出的参数调整：现金下限 10% → 30% → 20%

抗跌既然由**权益暴露**决定，就可以把它量化。跨策略横截面比较得到：

| 窗口 | corr(最大权益暴露, 最大回撤) |
|---|---:|
| 2008（2007-01~2012-12） | **-0.994** (n=8) |
| 2015（2013-01~2017-12） | **-0.887** (n=8) |
| 主样本（2019-01~2026-09） | -0.353（该窗口各策略暴露都被追到 80~96%，区分度丧失）|

用 2008-10-28（熊底当日）暴露拟合更干净：**corr = -0.980**，过原点斜率 → **回撤 ≈ -0.82 × 权益暴露%**。

据此扫描 `min_cash_pct`（脚本 `scripts/experiment_cash_floor.py`）：

| 现金下限 | 主样本年化 | 主样本最大回撤 | 峰值暴露 | 2008 窗口 | 2015 窗口 |
|---:|---:|---:|---:|---|---|
| 10% | 8.67% | -9.56% | 90.4% | 4.02% / -14.03% | 6.90% / -4.87% |
| **20%（现行）** | **8.43%** | **-9.56%** | **81.9%** | 不变 | 不变 |
| 30%（2026-09-10~09-11） | 7.92% | -9.17% | 72.5% | 不变 | 不变 |
| 40% | 7.11% | -7.43% | 62.7% | 不变 | 不变 |

- **2008/2015 四档完全相同**：那两段暴露本就只有 22.3% / 40.6%，闸门未被触及 → 该旋钮只在「高暴露时期」起作用，正是需要它的时期。
- **单位暴露效率几乎不变**（0.283%→0.268%）：**这是纯降杠杆，不是免费改善**。
- 参数沿革：`min_cash_pct` **10% → 30%**（2026-09-10，主动降杠杆，峰值暴露 90%→~72%，代价约 0.75pt 年化）→ **30% → 20%**（2026-09-11，按用户设定回调，个股上限 50%→60%，代价是峰值暴露回到 ~82%、主样本最大回撤 -9.17%→-9.56%）。

值得注意的是，**当下网格的机械信号是加仓而非减仓**（2026-09-10 股息率多在 5–6% 买入区）——「高暴露」与「该买入」是同一件事的两面。因此调整方向不是「不买」，而是「买，但设上限」。详细推导与当日信号见 [稳健性补记](backtests/ROBUSTNESS_NOTE.md)。

### 分红质量筛查挡掉了什么

把质量筛查整个关掉（`no_quality`），全样本年化由 8.67% 升到 9.11%、2023 年起由 14.51% 升到 **15.42%**。差异高度集中于一只标的——**华润江中**：它因派息率长期高于 100%（2022-06 前后按模型算得 103.6%）被判为 `risk`，网格从未买入，而回测区间内它恰好是大牛股，全样本少赚约 5.9 万元、2022 年起少赚 5.7 万元。

**这不等于「质量筛查是错的」**：回测用的是今天的清单，等于提前知道哪些标的后来的表现好（幸存者偏差）；质量筛查的意义在于规避「高股息但分红不可持续」的陷阱股，代价本来就表现为偶尔错过事后走强的标的。而且派息率是模型用 TTM EPS 与财年 DPS 回算的，口径不完全对齐时会被高估。**结论是「值得进一步核查规则阈值」，而不是「应当关闭筛查」。**
